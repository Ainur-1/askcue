# Pikabaka: интерфейс, сосредоточенный на разговоре

Исходный checkpoint приложения: `401f987`. Эксперименты находятся в ветке `codex/design-mockups` и не подключены к React-приложению или установленной Pika.

`pikabaka-concepts.html` — интерактивные макеты для просмотра в чате Codex. Все данные в них вымышлены. Действия меняют только состояние макета: микрофон, экран, провайдеры и реальные файлы не используются.

## Два направления

- **Рабочая область.** Полное окно: четыре постоянных раздела, разговор слева, ответ справа. Для подготовки, длинных разговоров и работы с материалами.
- **Фокус.** Компактное окно: последний вопрос и короткий ответ, остальные действия раскрываются по запросу. Для использования во время звонка.

Оба направления — одна система: нейтральные поверхности, один спокойный акцент, читаемый текст и одинаковые названия действий. Светлая и тёмная темы следуют окружению; в макете их можно выбрать в настройках.

## Сохранение возможностей

| Возможность текущей Pika | Место в макете |
| --- | --- |
| Подсказать, уточнить, сократить, переформулировать | Основные действия около ответа |
| Следующие вопросы, резюме, идеи, код, переговоры | «Все действия» |
| Голосовой вопрос | Поле ввода и «Все действия» |
| Полный скриншот и выделенная область | «Экран» и «Все действия» |
| Транскрипт, перевод, выбор фразы для вопроса | «Разговор», кнопка перевода, нажатие на реплику |
| Выбор модели и собственные провайдеры | Верхняя панель; Настройки → Модели |
| Микрофон, системный звук, STT и сегментация | Настройки → Аудио |
| Системный прокси и диагностика | Настройки → Общие |
| Скрытие окна, сквозные клики, непрозрачность, маскировка | Настройки → Окно |
| Горячие клавиши | Настройки → Клавиши; поддержка всех основных действий сохраняется |
| Поиск по встречам, просмотр, заметки, экспорт и follow-up письмо | Встречи → выбранная запись |
| Календарь | Встречи → Календарь |
| Резюме, профиль, вакансии, подготовка и документы RAG | Материалы |

## Что нужно решить перед реализацией

1. Предпочтительна ли рабочая область, компактное окно или оба режима одной программы.
2. Какие действия заслуживают постоянного места, а какие остаются в «Все действия».
3. Насколько крупным должен быть текст ответа и сколько транскрипта нужно видеть одновременно.

Упрощение относится к визуальной иерархии, а не к удалению функций. Редкие и чувствительные настройки остаются доступными, но не занимают место рядом с ответом.
